# Drive Original

Google Drive의 **원본 파일 바이트**를 브라우저와 서비스 워커로 직접 전달하는 PWA입니다. 같은 origin의 최소 서버리스 세션 API가 인증 상태를 맡습니다.

## 현재 운영 버전 — 1.23.1

배속·이미지 탐색 문구·키보드 초점과 설정 재진입을 고쳤습니다. 긴 파일명은 두 줄과 전체 파일명 창으로 확인하고, 하위 폴더 포함은 선택한 폴더 범위에서 탐색합니다. 음성·자막 확인의 반복 요청을 줄이고 실패/지원 제한과 재시도를 구분했습니다. 작은 화질 정보, 짧은 탐색 피드백, 즉시 오버레이 숨김과 모바일 간격·메뉴를 정돈했습니다. 기존 주소에 운영 반영했으며 실제 PC Chrome과 연결된 Android에서 검증했습니다. [변경 및 검증](memory/RELEASE-1.23.1.md)을 참고하세요.

## 이전 운영 버전 — 1.23.0

목록·PC/모바일 재생기를 간결하게 재디자인하고, 로딩 진행률·중앙/외곽 터치·재생 아이콘을 고쳤습니다. 반복 UI 처리와 MP4 검사 객체 생성을 줄였으며 실제 뷰너 영상으로 PC와 연결된 Android를 확인했습니다. 사용자 승인 후 기존 주소에 운영 반영했습니다. [변경 및 검증](memory/RELEASE-1.23.0.md)을 참고하세요.

## 이전 운영 버전 — 1.22.1

[운영 앱](https://drive-original-v2-candidate.drive-original-cloudflare-candidate.workers.dev/)에 1.22.1을 반영했습니다. 기존 GitHub Pages 주소도 이 앱으로 연결됩니다. 기존에 사용하던 Worker 주소를 유지해 계정 연결을 이어가며, 일반 파일 이동·휴지통 작업도 기존 권한·상태 확인 절차를 거쳐 실행합니다.

아이폰 재생을 막던 모듈 문법과 정상 MOV 구조 판정을 고쳤습니다. 세로 쇼츠·PC 플레이어·다중 선택 UI를 정돈하고, 정지는 영상 중앙에만 두며 더블클릭 확대를 막았습니다. 운영 파일65개와 캐시51개, 오프라인 실행 및 실제 아이폰 MP4·MOV 재생/탐색·세로 버튼 배치를 확인했습니다. [1.22.1 반영 근거](memory/RELEASE-1.22.1.md)를 참고하세요. 전체 명세의 실제 인수는 아직 완료되지 않았으며 실제 BMP·장시간 처리 자원·재생 중 업데이트 조건과 물리 손가락·VoiceOver 등의 확인은 [기존 남은 검증](memory/RELEASE-1.22.0.md)에 구분해 기록했습니다.

기존 GitHub Pages origin에 설치한 앱은 운영 주소에서 새로 열거나 설치해야 할 수 있습니다. 이전 주소의 설정·캐시·미동기화 상태를 삭제하지 않으며, 서로 다른 origin의 상태를 자동으로 복사했다고 보장하지 않습니다.

## 재생기 조작 방식

플레이어는 일시정지 중에도 기본적으로 컨트롤을 숨깁니다. PC에서는 커서를
하단으로 이동하면 컨트롤을 엽니다. 모바일에서는 중앙 정사각형을 한 번
터치해 재생·정지하고, 그 외곽이나 네 모서리를 한 번 터치해 컨트롤을 엽니다.
컨트롤이 보일 때 같은 외곽이나 버튼이 없는 조작 여백을 다시 누르면 즉시 숨깁니다.
`Tab`으로 키보드 제어에 접근할 수 있고, 마우스로 버튼을 누른 뒤 `Space`는
마지막 버튼을 재실행하지 않고 재생/일시정지를 제어합니다. 플레이어의
뒤로가기 한 번은 플레이어만 닫고, 그 다음 탐색은 폴더 이력을 따릅니다.

같은 계정의 재인증은 현재 목록과 재생 상태를 보존하고, 개별 파일 접근
거부는 전체 계정 로그아웃과 구분합니다. 만료 시 필요한 사용자 연결 갱신은
기존 화면을 지우지 않고 제공합니다. 무기한 자동 로그인을 보장하지 않습니다.
Chrome/WebKit·가상 Google API 검증과 실제 iPhone/두 실기기 검증의 경계는
`memory/IMMERSIVE-20260919.md`에 기록되어 있습니다.

## 정확히 무엇을 하는가

휴지통 이동·폴더 이동을 계정별 파일 작업 기록으로 보관하고, Drive의 별도 GET으로 확인한 항목만 완료 처리합니다. 응답 유실·404는 성공이 아니며, 새로고침 복구는 쓰기를 재전송하지 않습니다. 사용자가 같은 작업을 다시 선택한 경우에도 먼저 원래 버전·상태가 그대로인지 확인합니다. Web Locks 또는 기록 저장을 사용할 수 없으면 파일 변경만 중단합니다. 현재 운영 버전에서는 이 확인 절차를 유지하며 일반 파일 변경을 허용합니다. 실제 검증은 최종 결과에 기록한 유한 범위입니다.

1. 같은 origin의 인증 시작·콜백·세션 API를 통해 사용자가 Drive 권한을 승인합니다. 실제 PC·Android 인증과 복구 결과의 적용 범위는 최종 보고서에 보존하며, 물리 iPhone Chrome·홈 화면 PWA 검사는 후속 항목입니다.
2. Drive API에서 영상과 이미지 목록을 불러옵니다.
3. 화면에 필요한 카드만 단계적으로 렌더링하고, 제한된 동시성 큐로 썸네일을 불러옵니다. GIF 카드는 분리된 이미지에서 한 프레임만 320×320 캔버스에 그린 뒤 원본 이미지를 해제하므로 목록에서 움직이지 않습니다.
4. 영상은 OPFS 용량 확인이나 원본 전체 저장을 기다리지 않고 즉시 `Range` 원본 스트림을 시작합니다. 앱 전용 임시 디스크와 제한된 메모리는 분류된 Range 전송 오류가 제한된 재시도 뒤 반복되거나 무결성 검증이 실패했을 때 같은 원본 바이트를 보조하는 경로입니다.
5. 재생기가 요청한 `Range` 바이트 구간은 서비스 워커가 가로채 필요한 부분만 전달하고, 실제 응답이 부분 전송인지 검증합니다. Drive가 정상 `206`의 `Content-Range`를 CORS에서 숨기면 알려진 원본 크기와 노출된 `Content-Length`가 요청 전체 구간과 정확히 일치할 때만 범위를 복원하며, 짧거나 모호한 응답은 계속 실패 처리합니다. 서비스 워커는 요청한 창에 속한 메모리 토큰만 Drive `files.get?alt=media`에 붙이며, 401이면 같은 창에서만 토큰을 갱신하고 동일한 범위 요청을 한 번 재시도합니다.
6. Range의 일시 전송 실패는 한 사용자 재생 의도의 제한된 예산 안에서 한 번 다시 연결합니다. 반복 실패·무결성 오류 뒤에는 안전 한도 안의 OPFS 또는 제한된 메모리로 같은 원본 전체를 복구하며, 같은 파일의 전체 다운로드와 Range 요청을 동시에 중복 실행하지 않습니다.
7. 원본 경로가 실패하면 재시도·닫기가 가능한 오류를 표시합니다. Google 호환 재생(미리보기)과 Drive에서 열기는 사용자가 직접 선택할 때만 실행되며, 인증·전송·저장공간·코덱 오류를 자동 Google iframe 전환으로 끝내지 않습니다. 수동 Google 미리보기의 문서 로드는 실제 재생이나 원본 화질의 증거가 아닙니다. 보조 동작은 하나의 하단 제어와 함께 숨겨지고, 키보드/보조기술용 제어 진입점은 따로 유지합니다.
8. 파일 이동 대상은 My Drive와 접근 가능한 공유 드라이브의 폴더를 끝까지 검색합니다.
9. 쇼츠 이전·다음·랜덤 및 랜덤 정렬은 현재 대상 폴더에서 수집한 전체 미디어를 사용하며, 계정에서 아직 보지 않은 항목을 본 항목보다 먼저 무작위 배치합니다.
10. 카드와 플레이어의 하트로 좋아요를 관리하고, **좋아요** 필터에서 원래 폴더와 관계없이 한 번에 모아볼 수 있습니다. 좋아요 파일은 계정 상태에 저장된 파일 ID로 직접 조회하므로 전체 Drive 재귀 수집의 성공 여부에 의존하지 않습니다. 시청·좋아요 상태는 해당 Google Drive 계정의 비공개 `appDataFolder` JSON과 계정별 로컬 캐시를 합쳐 기기 간 동기화합니다.
    새 시청 기록은 영상의 실제 프레임 진행 또는 이미지 디코딩 후 화면 표시를 확인한 뒤 남깁니다. 열기 실패·일시정지 프레임만으로 미시청 후보에서 제외하지 않으며, 과거 시청 기록은 그대로 보존합니다. 로딩 중에는 측정 가능한 버퍼·저장 진행률을 표시하고, 연결·저장 실패에는 필요한 조치를 안내합니다.
11. 모바일 플레이어의 중앙 영역을 빠르게 두 번 탭하면 좋아요를 켜거나 끕니다. 뒤로가기 예약 영역을 제외한 영상의 좁은 좌우 바깥 영역은 10초 이동을 유지합니다. 맨 왼쪽 가장자리의 이동 제스처는 뒤로가기로 예약하여 영상 넘기기와 동시에 실행되지 않으며, 움직이지 않고 한 번 탭하면 컨트롤 표시를 전환합니다. 플레이어가 닫힌 라이브러리에서는 상위 폴더나 이전 필터로 돌아갑니다.
12. 카드 길게 누르기(PC는 우클릭도 지원)로 여러 파일을 선택해 휴지통 이동 또는 다른 폴더 이동을 일괄 실행할 수 있습니다.
13. 영상은 플레이어 버튼 또는 `,` / `.` 키로 약 1프레임씩 이동할 수 있습니다.

적응형 판단은 **전송 방식만** 선택합니다. Range 경로와 임시 디스크·메모리 경로는 모두 Drive 원본 파일 바이트를 그대로 사용하므로 화질 우선순위를 낮추지 않습니다. Google 호환 재생은 원본 화질을 확인할 수 없는 마지막 수단이며, 앱 밖 Drive 열기는 사용자가 직접 선택할 때만 실행됩니다.

## 재생 우선순위

1. **Drive 원본 파일 · Range 무변환 전송**: 영상은 저장소 점검이나 전체 다운로드를 선행하지 않고 유효한 `206` Range 응답으로 필요한 바이트부터 점진적으로 전송합니다. Drive가 Range를 무시하고 `200` 전체 응답을 반환하면 이를 **Drive 원본 파일 · 연속 전송**으로 사실대로 표시합니다.
2. **Drive 원본 파일 · 임시 디스크**: Range 재연결과 무결성 검증으로 직접 재생을 이어가지 못한 뒤에만, 쓰기 가능한 OPFS와 예상 여유 공간의 80% 안전 한도를 확인해 같은 원본 전체를 복구합니다.
3. **Drive 원본 파일 · 메모리**: 쓰기 가능한 OPFS가 없고 Range도 이어가지 못할 때 모바일 24MiB·데스크톱 96MiB까지 자동, 사용자 확인 후 각각 64MiB·256MiB까지 허용합니다.
4. **Google 미리보기 · 재생·화질 미확인**: 사용자의 명시적 선택으로만 여는 외부 문서입니다. 앱 내부 원본 재생 성공에 포함하지 않으며, 원본 다시 시도·Drive 직접 열기·제어 숨기기를 하단에서 제공합니다.
5. **Drive 직접 열기**: 앱 내부 호환 재생도 불가능할 때 사용자가 선택하는 최종 탈출 경로입니다.

플레이어를 처음 열 때와 원본 전송 검증이 끝나기 전에는 `원본 확인 중`만 표시합니다. 원본 파일 바이트 전달 사실과 화면상 해상도·브라우저 코덱 지원은 별개의 정보입니다.

## 중요한 한계

**v1.20.1 검증 후보:** 앱이 화면에 표시되고 Google 계정이 연결된 온라인 상태에서는 약 15초 간격으로 다른 작성자의 상태를 다시 읽습니다. 백그라운드·오프라인에서는 주기적 조회를 멈추고 복귀·재연결 시 재개하며, 서버의 재시도 대기와 오류 후 지연을 보존합니다. 즉시 푸시 동기화가 아니므로 저장 완료 표시가 다른 기기의 수신 완료를 보증하지 않습니다. 이 후보의 실제 iPhone 모서리 제스처와 실제 Google 계정의 두 기기 검증은 아직 열려 있습니다. 재현·자동 검증 결과와 실기기 절차는 `memory/ACCEPTANCE-20260917.md`를 참고하세요. 이 브랜치의 후보 버전 표시는 운영 배포 완료를 뜻하지 않습니다.

- **네트워크 전송 없는 스트리밍은 불가능합니다.** 재생하려면 필요한 바이트가 네트워크를 통해 기기의 임시 버퍼로 들어와야 합니다. 앱은 미디어를 Cache Storage에 넣거나 파일 앱·사진 앱에 별도 저장하지 않지만, 브라우저의 일반 HTTP 캐시는 응답 일부를 짧게 보관할 수 있습니다.
- 원본 파일 바이트 전달과 재생 가능성은 별개입니다. 브라우저가 원본 코덱 또는 컨테이너를 지원하지 않으면 동일 바이트의 전체 저장만으로 해독할 수 있다고 보장하지 않습니다. 제품 Q1 재포장 통합은 아직 미완료이며, 실패를 수동 Google 미리보기 성공으로 계산하지 않습니다.
- iPhone에서는 **MP4 또는 MOV 컨테이너 + H.264 또는 HEVC 영상 + AAC 오디오** 조합이 가장 안정적입니다. MKV와 일부 WebM, 특수 오디오 코덱은 실패할 수 있습니다.
- 현재 앱은 코덱을 변환하지 않습니다. 디코딩 가능성은 기기의 지원 범위에 달려 있으며, 별도 변환 서버가 있더라도 변환본을 원본 바이트와 동일하다고 표시하지 않습니다.
- 전체 파일 보조 경로는 쓰기 가능한 OPFS와 실제 여유 공간을 먼저 확인합니다. OPFS 비지원 환경에서는 메모리 상한을 넘는 파일을 자동 다운로드하지 않습니다. 사전 용량 검사나 쓰기 도중 할당량이 소진되면 부분 파일과 잠금을 정리하고 저장공간 오류로 멈추며, 큰 파일은 사용자 확인 또는 호환 재생의 명시적 선택을 요구합니다.
- 브라우저 버전 이름 대신 실제 OPFS 쓰기 기능과 저장 공간을 검사합니다. 메인 스레드 `createWritable()`이 없으면 디스크 경로를 선택하지 않고 Range 및 제한된 메모리 원본으로 복구합니다.
- Google OAuth 액세스 자격 증명은 짧게 유효합니다. V2-04A 후보에서 페이지와 서비스 워커는 `{accessToken, expiresAt, account, revision}`만 메모리에 두며, 세션 갱신은 같은 origin 세션 API가 담당합니다. 필요한 사용자 승인 또는 재연결이 있으면 기존 화면을 지우지 않고 안내합니다.
- 다운로드가 금지된 공유 파일은 원본 스트리밍도 할 수 없습니다.
- GIF는 목록 성능을 위해 카드마다 한 정지 프레임만 표시합니다. 정지 프레임을 만들 수 없는 경우에만 GIF 자리표시자를 유지하며, 파일을 열면 원본 GIF가 재생될 수 있습니다.
- 시청·좋아요 상태는 기기별 작성자 파일을 읽고 병합합니다. 서로 다른 기기가 같은 JSON을 덮어써 기록이 사라지는 경쟁을 방지하며, 기존 단일 파일은 읽기 전용 이관 원본으로 보존합니다. 같은 기기의 탭은 Web Locks로 직렬화하고, 잠금 미지원 환경은 실행 컨텍스트별 파일을 사용합니다. 항목별 최신 시각이 우선하며 정확히 같은 시각의 충돌은 좋아요 취소가 우선합니다. 모든 기기의 v1.20.0 이상 사용을 권장합니다.
- Google 계정 및 공유 드라이브 정책에 따라 읽기 전용 폴더나 드라이브 간 이동이 제한될 수 있습니다.

## 1. 웹에 올리기

런타임 빌드가 필요 없는 공개 셸은 `node scripts/build-pages.cjs`로 `_site/`에 준비할 수 있습니다. 이 절은 기존 정적 셸의 패키징 방법만 설명하며, V2-04A의 인증 서버리스 API를 배포하거나 동작을 검증했다는 뜻이 아닙니다. V2-04A는 셸과 `/auth/*`, `/api/session/*`가 같은 HTTPS origin에서 제공되어야 하므로, 정적 셸만의 GitHub Pages 게시으로는 그 인증 계약을 충족하지 않습니다.

로컬 확인:

```bash
cd drive-original
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다. 실제 iPhone 사용은 HTTPS 배포 주소가 필요합니다.

## 2. Google Drive 연결

**후보판 연결:** 사용자가 **Google Drive 연결하기**를 누르면 현재 페이지와 정확히 같은 HTTPS origin의 인증 시작점으로 이동합니다. 콜백과 세션 API도 그 origin에서만 처리합니다. Google OAuth 클라이언트 ID·client secret·refresh credential은 페이지 설정이나 `localStorage`에 입력·저장하지 않습니다.

인증 서버리스 계층은 암호화된 refresh credential과 서버 세션 상태를 소유합니다. `{accessToken, expiresAt, account, revision}`이라는 짧은 Drive access credential과 검증된 기능 권한 `capabilities`는 필요한 동안 페이지 메모리에 둡니다. 서비스 워커에는 Drive 읽기 권한이 있을 때만 재생에 필요한 credential을 전달합니다. 페이지는 홈 화면 앱의 OAuth 복귀를 판별할 때 현재 HttpOnly 세션에서 파생된 비밀 아닌 marker도 메모리에서만 비교하며, 이 값은 URL·로컬 저장소·서비스 워커로 보내지 않습니다. 새로고침·서비스 워커 종료·브라우저 재시작 뒤에도 그 credential이나 marker를 `localStorage`, Cache Storage, IndexedDB에 복원하지 않습니다.

일부 권한만 승인했을 때는 가능한 기능을 유지합니다. `drive.readonly`는 목록·원본 재생을 허용하고 파일 수정은 허용하지 않습니다. 앱 데이터 권한이 없으면 시청·좋아요의 계정 동기화를 멈추고 대기 중인 로컬 기록은 보존합니다. `drive.file`이나 메타데이터 권한만으로 전체 라이브러리 읽기 권한이 있다고 판단하지 않습니다. 추가 권한이 필요한 기능은 사용자가 명시적으로 재연결할 수 있으며, 동의 창을 자동 반복하지 않습니다. 후보판의 일반 파일 수정 잠금은 Google 권한과 별도로 유지됩니다.

세션 API는 정확한 `Origin`만 허용하고, 상태를 바꾸는 요청은 해당 origin 확인과 별도 CSRF 방어를 모두 통과해야 합니다. 콜백 허용 주소도 실제 같은 HTTPS origin의 정확한 경로로 제한합니다. 이 문서는 일반 사용자가 클라이언트 ID를 재정의하거나 임의 origin을 추가하는 절차를 제공하지 않습니다.

같은 origin의 Cloudflare Worker/Google OAuth 시작·콜백 어댑터와 PC Chrome 세션 복구는 V2-04B 후보에서 확인했습니다. iPhone 홈 화면 앱은 브라우저와 분리된 쿠키 저장소를 쓰므로 standalone 전용 인증 창·복귀 경로를 따로 사용하며, 실제 iPhone 결과는 여전히 실기기 검증 전입니다.

## 3. iPhone에 설치

아래는 같은 HTTPS origin 인증 후보의 의도한 사용 흐름입니다. 실제 iPhone 로그인·복귀는 V2-04B에서 아직 검증해야 하며, 이 문서만으로 설치 또는 연결 성공을 보장하지 않습니다.

1. iPhone Safari에서 배포 주소를 엽니다.
2. Safari의 **공유 → 홈 화면에 추가**를 선택합니다.
3. 홈 화면의 Drive Original을 실행합니다.
4. 홈 화면 앱 안의 **Google Drive에 연결**을 눌러 열린 Google 로그인 창을 완료하고 앱으로 돌아옵니다.

설치 뒤 Safari/Chrome 탭에서 새로 로그인해도 그 쿠키가 기존 홈 화면 앱으로 복사되지는 않습니다. 연결은 홈 화면 앱 안에서 시작해야 하며, 결과를 확인하지 못한 경우 앱은 자동으로 OAuth를 반복하지 않고 오류를 표시합니다.

## 개인정보와 보안

- 권한: `https://www.googleapis.com/auth/drive`(Drive 파일 보기·수정), `https://www.googleapis.com/auth/drive.appdata`(앱 전용 시청·좋아요 상태 동기화)
- 인증 상태(후보판): 같은 origin의 최소 서버리스 세션 API가 암호화된 refresh credential과 세션을 소유합니다. 페이지는 짧은 access credential과 검증된 기능 권한을 메모리에만 두며, 서비스 워커에는 허용된 원본 읽기에 필요한 credential만 전달합니다. standalone OAuth 복귀 판별용 비밀 아닌 세션 marker도 페이지 메모리에서만 비교합니다. refresh credential과 client secret은 전달하지 않습니다.
- 미디어 경로: 브라우저 ↔ Google Drive API
- 인증 서버는 Drive 미디어 바이트를 중계·캐시·변환하지 않으며, Drive 파일 수정 경로도 소유하지 않습니다.
- 미디어 Cache Storage 저장: 없음
- 계정 상태 동기화: Drive의 앱 전용 비공개 `appDataFolder`에 파일 ID별 시청 시각과 좋아요 상태만 저장하며, 미디어 자체는 복제하지 않음
- 좋아요 조회 실패 복구: 이미 이 기기에 알려진 좋아요는 계속 표시하고, 나머지는 파일 ID별로 다시 조회하며, 화면을 벗어난 이전 요청과 상태 문구는 즉시 무효화
- 로컬 저장소: OAuth client ID·access token·만료 시각·refresh credential·서버 세션은 저장하지 않습니다. 비밀이 아닌 계정별 시청·좋아요 상태 캐시는 별도 데이터 경로에서만 유지됩니다.
- **로그아웃:** 현재 기기의 현재 세션만 종료하고 메모리 access credential을 제거합니다.
- **모든 세션 연결 해제(disconnect):** 서버에 보관한 해당 계정의 앱 session과 refresh credential을 삭제하도록 요청합니다. Google revoke의 성공 여부가 불확실하면 성공으로 표시하지 않습니다.
- 같은 origin Cloudflare/Google 어댑터와 PC Chrome 세션은 V2-04B 후보에서 확인했습니다. iPhone 브라우저와 홈 화면 앱의 실제 콜백·세션 유지는 별도 실기기 인수 항목입니다.

## 기술 근거

- Google Drive API의 `files.get`과 `alt=media`는 Drive에 저장된 바이너리 파일 내용을 반환합니다.
- Drive API는 `Range` 헤더를 이용한 부분 다운로드를 지원합니다.
- HTTP 범위 요청은 영상 재생기의 임의 위치 탐색과 부분 전송에 쓰입니다.
- OPFS는 앱 원본의 사설 저장 영역이며, 지원 브라우저에서 큰 원본의 임시 디스크 버퍼로 사용합니다.
- `Retry-After`는 초 단위와 HTTP 날짜 형식을 모두 존중하며, 긴 대기는 조기 자동 재시도 대신 사용자에게 남은 시간을 알립니다.
- V2-04A 후보에서도 Drive REST와 원본 미디어 Range 요청은 브라우저/서비스 워커가 Google API에 직접 보냅니다. 인증 서버리스 계층은 인증·세션만 맡습니다.
