# Drive Original

Google Drive의 저화질 미리보기 대신 **원본 파일 바이트**를 iPhone Safari로 전달하는 정적 PWA입니다. 별도 앱 서버나 데이터베이스가 필요하지 않습니다.

## 정확히 무엇을 하는가

1. Google Identity Services로 사용자가 직접 Drive 보기·수정 권한을 승인합니다.
2. Drive API에서 영상과 이미지 목록을 불러옵니다.
3. 화면에 필요한 카드만 단계적으로 렌더링하고, 제한된 동시성 큐로 썸네일을 불러옵니다. GIF 카드는 분리된 이미지에서 한 프레임만 320×320 캔버스에 그린 뒤 원본 이미지를 해제하므로 목록에서 움직이지 않습니다.
4. 영상은 파일 크기·OPFS 쓰기 가능 여부·남은 저장 공간을 먼저 확인합니다. 안전 자동 한도 안의 영상은 원본 전체를 앱 전용 임시 디스크에 청크 단위로 준비하고, 큰 파일·크기 미상·OPFS 비지원 환경은 즉시 `Range` 원본 스트림을 시작합니다.
5. 재생기가 요청한 `Range` 바이트 구간은 서비스 워커가 가로채 필요한 부분만 전달하고, 실제 응답이 부분 전송인지 검증합니다. Drive가 정상 `206`의 `Content-Range`를 CORS에서 숨기면 알려진 원본 크기와 노출된 `Content-Length`가 요청 전체 구간과 정확히 일치할 때만 범위를 복원하며, 짧거나 모호한 응답은 계속 실패 처리합니다. 서비스 워커는 요청한 창에 속한 메모리 토큰만 Drive `files.get?alt=media`에 붙이며, 401이면 같은 창에서만 토큰을 갱신하고 동일한 범위 요청을 한 번 재시도합니다.
6. 처음 선택한 원본 경로가 실패하면 나머지 원본 경로로 교차 복구합니다. 임시 디스크 준비 실패는 Range로, Range 반복 실패·무결성 오류는 임시 디스크로 이어지며, OPFS를 쓸 수 없을 때만 작은 파일을 기기별 메모리 한도 안에서 보조합니다. 같은 파일의 전체 다운로드와 Range 요청을 동시에 중복 실행하지 않습니다.
7. Drive 정책이 원본 다운로드를 제한하거나, 원본 Range·임시 디스크·제한된 메모리 경로가 모두 소진되거나, 검증된 원본 파일에서 브라우저 코덱 비호환이 확인된 경우에만 앱 안의 Google 호환 재생기로 자동 전환합니다. 이 경로는 Google 변환본일 수 있으므로 원본 화질을 확인할 수 없으며, 외부 Drive 페이지는 자동으로 열지 않습니다.
8. 파일 이동 대상은 My Drive와 접근 가능한 공유 드라이브의 폴더를 끝까지 검색합니다.
9. 쇼츠 이전·다음·랜덤 및 랜덤 정렬은 현재 대상 폴더에서 수집한 전체 미디어를 사용하며, 계정에서 아직 보지 않은 항목을 본 항목보다 먼저 무작위 배치합니다.
10. 카드와 플레이어의 하트로 좋아요를 관리하고, **좋아요** 필터에서 원래 폴더와 관계없이 한 번에 모아볼 수 있습니다. 시청·좋아요 상태는 해당 Google Drive 계정의 비공개 `appDataFolder` JSON과 계정별 로컬 캐시를 합쳐 기기 간 동기화합니다.
11. 모바일 플레이어의 중앙 영역을 빠르게 두 번 탭하면 좋아요를 켜거나 끕니다. 영상의 좁은 좌우 바깥 영역은 기존처럼 10초 이동을 유지하며, 플레이어가 닫힌 라이브러리에서는 왼쪽 화면 모서리 스와이프로 상위 폴더나 이전 필터로 돌아갑니다.
12. 카드 길게 누르기(PC는 우클릭도 지원)로 여러 파일을 선택해 휴지통 이동 또는 다른 폴더 이동을 일괄 실행할 수 있습니다.
13. 영상은 플레이어 버튼 또는 `,` / `.` 키로 약 1프레임씩 이동할 수 있습니다.

적응형 판단은 **전송 방식만** 선택합니다. Range 경로와 임시 디스크·메모리 경로는 모두 Drive 원본 파일 바이트를 그대로 사용하므로 화질 우선순위를 낮추지 않습니다. Google 호환 재생은 원본 화질을 확인할 수 없는 마지막 수단이며, 앱 밖 Drive 열기는 사용자가 직접 선택할 때만 실행됩니다.

## 재생 우선순위

1. **Drive 원본 파일 · 임시 디스크** 또는 **Drive 원본 파일 · Range 무변환 전송**: 알려진 크기가 모바일 64MiB·데스크톱 256MiB 이하이고 OPFS 쓰기와 예상 여유 공간의 80% 한도가 확인되면 임시 디스크를 먼저 사용합니다. 그 밖에는 유효한 `206` Range 응답으로 필요한 바이트만 점진적으로 전송합니다.
2. **남은 Drive 원본 경로로 교차 복구**: 첫 원본 경로가 실패하면 아직 시도하지 않은 임시 디스크 또는 Range 경로를 사용합니다. Drive가 `200` 전체 응답을 반환하면 이를 **Drive 원본 파일 · 연속 전송**으로 표시합니다.
3. **Drive 원본 파일 · 메모리**: 쓰기 가능한 OPFS가 없고 Range도 이어가지 못할 때 모바일 24MiB·데스크톱 96MiB까지 자동, 사용자 확인 후 각각 64MiB·256MiB까지 허용합니다.
4. **Google 호환 재생 · 원본 화질 미확인**: 확정된 원본 코덱 비호환·다운로드 제한·안전 저장 한도 초과 또는 모든 가능한 원본 계층 실패 후에만 사용합니다.
5. **Drive 직접 열기**: 앱 내부 호환 재생도 불가능할 때 사용자가 선택하는 최종 탈출 경로입니다.

플레이어를 처음 열 때와 원본 전송 검증이 끝나기 전에는 `원본 확인 중`만 표시합니다. 원본 파일 바이트 전달 사실과 화면상 해상도·브라우저 코덱 지원은 별개의 정보입니다.

## 중요한 한계

- **네트워크 전송 없는 스트리밍은 불가능합니다.** 재생하려면 필요한 바이트가 네트워크를 통해 기기의 임시 버퍼로 들어와야 합니다. 앱은 미디어를 Cache Storage에 넣거나 파일 앱·사진 앱에 별도 저장하지 않지만, 브라우저의 일반 HTTP 캐시는 응답 일부를 짧게 보관할 수 있습니다.
- 원본 파일 바이트 전달과 재생 가능성은 별개입니다. 브라우저가 원본 코덱 또는 컨테이너를 지원하지 않으면 동일 바이트를 전체 저장해도 해독할 수 없으므로 Google 호환 재생기로 전환합니다.
- iPhone에서는 **MP4 또는 MOV 컨테이너 + H.264 또는 HEVC 영상 + AAC 오디오** 조합이 가장 안정적입니다. MKV와 일부 WebM, 특수 오디오 코덱은 실패할 수 있습니다.
- 정적 웹앱만으로 모든 코덱을 원본 화질로 변환하는 것은 불가능합니다. 모든 형식의 원본 화질 재생을 보장하려면 FFmpeg 기반 서버 트랜스코딩 인프라가 필요합니다.
- 전체 파일 보조 경로는 쓰기 가능한 OPFS와 실제 여유 공간을 먼저 확인합니다. OPFS 비지원 환경에서는 메모리 상한을 넘는 파일을 자동 다운로드하지 않으며, 큰 파일은 사용자 확인 또는 호환 재생 선택을 요구합니다.
- Safari 26 이전처럼 OPFS 읽기는 지원하지만 메인 스레드 `createWritable()`이 없는 브라우저는 디스크 경로를 선택하지 않고 제한된 메모리 경로로 안전하게 강등됩니다.
- Google OAuth 액세스 토큰은 짧게 유효합니다. 앱이 조용한 갱신을 먼저 시도하며, 동의나 팝업이 필요하면 사용자가 다시 연결해야 합니다.
- 다운로드가 금지된 공유 파일은 원본 스트리밍도 할 수 없습니다.
- GIF는 목록 성능을 위해 카드마다 한 정지 프레임만 표시합니다. 정지 프레임을 만들 수 없는 경우에만 GIF 자리표시자를 유지하며, 파일을 열면 원본 GIF가 재생될 수 있습니다.
- 시청·좋아요 동기화는 개인용 앱에 맞춘 단일 상태 파일의 읽기·병합·쓰기 방식입니다. 별도 서버나 데이터베이스는 없으며, 여러 기기에서 정확히 같은 순간에 반대 동작을 하면 각 항목의 더 최근 변경 시각이 우선합니다.
- Google 계정 및 공유 드라이브 정책에 따라 읽기 전용 폴더나 드라이브 간 이동이 제한될 수 있습니다.

## 1. 웹에 올리기

이 폴더는 빌드가 필요 없는 정적 사이트입니다. HTTPS를 제공하는 GitHub Pages, Cloudflare Pages, Netlify 등에 폴더 내용을 그대로 배포하세요.

로컬 확인:

```bash
cd drive-original
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다. 실제 iPhone 사용은 HTTPS 배포 주소가 필요합니다.

## 2. Google Drive 연결

공식 배포 주소에서는 앱에 포함된 기본 웹 OAuth 클라이언트 ID를 사용합니다. 첫 화면에서 ID를 입력할 필요 없이 **Google Drive 연결하기**를 누르고 Google 로그인 창에서 계정과 Drive 권한을 확인하면 됩니다. 토큰 요청은 페이지 로드 중 자동으로 팝업을 열지 않고 사용자의 연결 버튼 클릭으로만 시작합니다.

기본 클라이언트 ID는 `376776089602-t0te7oadl7ki589fnfdfhs173gco2n0l.apps.googleusercontent.com`입니다. 클라이언트 ID는 웹앱에서 사용하는 공개 식별자이며 클라이언트 보안 비밀이 아닙니다.

### 자체 배포 또는 다른 Google Cloud 프로젝트 사용

공식 배포가 아닌 다른 origin에서 호스팅하거나 별도 Google Cloud 프로젝트를 사용하려면 다음 설정이 필요합니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 **Google Drive API**를 사용 설정합니다.
3. **Google Auth Platform / OAuth 동의 화면**을 구성합니다.
4. 앱이 테스트 상태라면 **테스트 사용자**에 본인의 Google 계정을 추가합니다.
5. **클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**을 선택합니다.
6. **승인된 JavaScript 원본**에 배포 사이트의 원본만 추가합니다.
   - 예: `https://example.com`
   - GitHub Pages 예: `https://조직명.github.io`
   - 경로와 마지막 슬래시는 넣지 않습니다.
7. 앱 설정의 **자체 배포 · 고급 OAuth 설정**에 생성된 `…apps.googleusercontent.com` 형식의 클라이언트 ID를 선택적으로 저장합니다.

입력란을 비우거나 앱 기본 ID를 저장하면 custom override가 제거되고 기본 연결 설정으로 돌아갑니다. 승인된 JavaScript 원본은 정확히 제한해야 다른 사이트에서 해당 OAuth 프로젝트를 무단 사용하기 어렵습니다.

## 3. iPhone에 설치

1. iPhone Safari에서 배포 주소를 엽니다.
2. Google Drive 연결을 완료합니다.
3. Safari의 **공유 → 홈 화면에 추가**를 선택합니다.
4. 홈 화면의 Drive Original을 실행합니다.

홈 화면 앱에서 Google 로그인 팝업이 완료되지 않으면 Safari 탭에서 먼저 연결하세요.

## 개인정보와 보안

- 권한: `https://www.googleapis.com/auth/drive`(Drive 파일 보기·수정)
- 액세스 토큰: 자동 로그인을 위해 토큰과 만료 시각을 이 브라우저의 로컬 저장소에 보관하고, 실행 중에는 메모리 및 서비스 워커 메모리에도 전달
- 장기 갱신 토큰: 사용하지 않음
- 미디어 경로: 브라우저 ↔ Google Drive API
- 자체 서버 업로드: 없음
- 미디어 Cache Storage 저장: 없음
- 계정 상태 동기화: Drive의 앱 전용 비공개 `appDataFolder`에 파일 ID별 시청 시각과 좋아요 상태만 저장하며, 미디어 자체는 복제하지 않음
- 로컬 저장소에 남는 값: 선택적으로 재정의한 OAuth 클라이언트 ID, 단기 액세스 토큰, 토큰 만료 시각, Drive 계정 ID로 분리된 시청·좋아요 상태 캐시
- 연결 해제 시 저장된 액세스 토큰을 삭제하고 Google에 토큰 폐기를 요청

## 기술 근거

- Google Drive API의 `files.get`과 `alt=media`는 Drive에 저장된 바이너리 파일 내용을 반환합니다.
- Drive API는 `Range` 헤더를 이용한 부분 다운로드를 지원합니다.
- HTTP 범위 요청은 영상 재생기의 임의 위치 탐색과 부분 전송에 쓰입니다.
- OPFS는 앱 원본의 사설 저장 영역이며, 지원 브라우저에서 큰 원본의 임시 디스크 버퍼로 사용합니다.
- `Retry-After`는 초 단위와 HTTP 날짜 형식을 모두 존중하며, 긴 대기는 조기 자동 재시도 대신 사용자에게 남은 시간을 알립니다.
- Google Identity Services의 토큰 모델은 브라우저에서 REST와 CORS로 Google API를 호출하도록 설계됐습니다.
