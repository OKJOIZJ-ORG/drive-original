# Drive Original

Google Drive의 저화질 미리보기 대신 **원본 파일 바이트**를 iPhone Safari로 전달하는 정적 PWA입니다. 별도 앱 서버나 데이터베이스가 필요하지 않습니다.

## 정확히 무엇을 하는가

1. Google Identity Services로 사용자가 직접 Drive 보기·수정 권한을 승인합니다.
2. Drive API에서 영상과 이미지 목록을 불러옵니다.
3. 화면에 필요한 카드만 단계적으로 렌더링하고, 제한된 동시성 큐로 썸네일을 불러옵니다. GIF 카드는 목록에서 자동 재생하지 않습니다.
4. 재생기가 요청한 `Range` 바이트 구간을 서비스 워커가 가로채 필요한 부분만 전달합니다.
5. 서비스 워커는 요청한 창에 속한 메모리 토큰만 Drive `files.get?alt=media`에 붙입니다. 401이면 같은 창에서만 토큰을 갱신하고 동일한 범위 요청을 한 번 재시도합니다.
6. 영상의 구간 스트림이 실패하면 전체 파일을 메모리에 내려받지 않고 중단합니다. 이미지는 기기별 안전 한도 안에서만 원본 메모리 버퍼를 보조 경로로 사용합니다.
7. 브라우저가 원본 코덱을 해독하지 못하면 내장 프리뷰가 아니라 최상위 Google Drive 탭으로 넘겨 로그인 쿠키 격리 문제를 피합니다.
8. 파일 이동 대상은 My Drive와 접근 가능한 공유 드라이브의 폴더를 끝까지 검색합니다.
9. 쇼츠 이전·다음·랜덤 및 랜덤 정렬은 현재 대상 폴더에서 수집한 전체 미디어를 사용합니다.
10. 카드 길게 누르기(PC는 우클릭도 지원)로 여러 파일을 선택해 휴지통 이동 또는 다른 폴더 이동을 일괄 실행할 수 있습니다.
11. 영상은 플레이어 버튼 또는 `,` / `.` 키로 약 1프레임씩 이동할 수 있습니다.

기본 경로와 이미지 보조 버퍼 경로는 원본 바이트를 사용합니다. Drive로 넘기기는 원본 스트림을 브라우저가 재생할 수 없을 때 사용자가 명시적으로 선택하는 복구 경로입니다.

## 재생 우선순위

1. **원본 구간 스트림**: 원본 화질, 필요한 바이트만 점진적으로 전송
2. **원본 이미지 임시 버퍼**: 직접 표시가 실패한 이미지만 메모리에 임시 저장하고 플레이어를 닫으면 해제
3. **Drive에서 열기**: 원본 영상 스트림이나 코덱을 브라우저가 처리하지 못할 때 최상위 Drive 탭으로 안전하게 넘김

## 중요한 한계

- **네트워크 전송 없는 스트리밍은 불가능합니다.** 재생하려면 필요한 바이트가 네트워크를 통해 기기의 임시 버퍼로 들어와야 합니다. 앱은 미디어를 Cache Storage에 넣거나 파일 앱·사진 앱에 별도 저장하지 않지만, 브라우저의 일반 HTTP 캐시는 응답 일부를 짧게 보관할 수 있습니다.
- 원본 화질과 재생 가능성은 별개입니다. 브라우저가 원본 코덱 또는 컨테이너를 지원하지 않으면 앱이 전체 영상을 내려받지 않고 Drive에서 열기 복구 화면을 표시합니다.
- iPhone에서는 **MP4 또는 MOV 컨테이너 + H.264 또는 HEVC 영상 + AAC 오디오** 조합이 가장 안정적입니다. MKV와 일부 WebM, 특수 오디오 코덱은 실패할 수 있습니다.
- 정적 웹앱만으로 모든 코덱을 원본 화질로 변환하는 것은 불가능합니다. 모든 형식의 원본 화질 재생을 보장하려면 FFmpeg 기반 서버 트랜스코딩 인프라가 필요합니다.
- 이미지 임시 버퍼는 전체 원본 이미지를 메모리에 담으므로 모바일은 350MB, 데스크톱은 2GB를 상한으로 사용합니다. 영상에는 이 전체 파일 보조 경로를 사용하지 않습니다.
- Google OAuth 액세스 토큰은 짧게 유효합니다. 앱이 조용한 갱신을 먼저 시도하며, 동의나 팝업이 필요하면 사용자가 다시 연결해야 합니다.
- 다운로드가 금지된 공유 파일은 원본 스트리밍도 할 수 없습니다.
- GIF는 목록 성능을 위해 카드에서 미리 재생하지 않습니다. 파일을 열면 원본 GIF가 재생될 수 있습니다.
- Google 계정 및 공유 드라이브 정책에 따라 읽기 전용 폴더나 드라이브 간 이동이 제한될 수 있습니다.

## 1. 웹에 올리기

이 폴더는 빌드가 필요 없는 정적 사이트입니다. HTTPS를 제공하는 GitHub Pages, Cloudflare Pages, Netlify 등에 폴더 내용을 그대로 배포하세요.

로컬 확인:

```bash
cd drive-original
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다. 실제 iPhone 사용은 HTTPS 배포 주소가 필요합니다.

## 2. Google Cloud 최초 설정

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 **Google Drive API**를 사용 설정합니다.
3. **Google Auth Platform / OAuth 동의 화면**을 구성합니다.
4. 앱이 테스트 상태라면 **테스트 사용자**에 본인의 Google 계정을 추가합니다.
5. **클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**을 선택합니다.
6. **승인된 JavaScript 원본**에 배포 사이트의 원본만 추가합니다.
   - 예: `https://example.com`
   - GitHub Pages 예: `https://조직명.github.io`
   - 경로와 마지막 슬래시는 넣지 않습니다.
7. 생성된 `…apps.googleusercontent.com` 형식의 클라이언트 ID를 앱 첫 화면에 붙여넣습니다.

클라이언트 ID는 공개 식별자이며 비밀번호가 아닙니다. 그래도 승인된 JavaScript 원본을 정확히 제한해야 다른 사이트에서 무단 사용하기 어렵습니다.

## 3. iPhone에 설치

1. iPhone Safari에서 배포 주소를 엽니다.
2. Google Drive 연결을 완료합니다.
3. Safari의 **공유 → 홈 화면에 추가**를 선택합니다.
4. 홈 화면의 Drive Original을 실행합니다.

홈 화면 앱에서 Google 로그인 팝업이 완료되지 않으면 Safari 탭에서 먼저 연결하세요.

## 개인정보와 보안

- 권한: `https://www.googleapis.com/auth/drive`(Drive 파일 보기·수정)
- 액세스 토큰: 자동 로그인을 위해 토큰과 만료 시각을 이 브라우저의 로컬 저장소에 보관하고, 실행 중에는 메모리 및 서비스 워커 메모리에도 전달
- 장기 갱신 토큰: 사용하지 않음
- 미디어 경로: 브라우저 ↔ Google Drive API
- 자체 서버 업로드: 없음
- 미디어 Cache Storage 저장: 없음
- 로컬 저장소에 남는 값: OAuth 클라이언트 ID, 단기 액세스 토큰, 토큰 만료 시각
- 연결 해제 시 저장된 액세스 토큰을 삭제하고 Google에 토큰 폐기를 요청

## 개발용 데모 화면

Google 계정 연결 없이 UI만 확인하려면 주소 끝에 `?demo=1`을 붙입니다.

```text
http://localhost:8080/?demo=1
```

데모 모드는 실제 Drive 요청을 보내지 않습니다.

## 기술 근거

- Google Drive API의 `files.get`과 `alt=media`는 Drive에 저장된 바이너리 파일 내용을 반환합니다.
- Drive API는 `Range` 헤더를 이용한 부분 다운로드를 지원합니다.
- HTTP 범위 요청은 영상 재생기의 임의 위치 탐색과 부분 전송에 쓰입니다.
- Google Identity Services의 토큰 모델은 브라우저에서 REST와 CORS로 Google API를 호출하도록 설계됐습니다.
