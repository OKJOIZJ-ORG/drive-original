# Q0 immutable original revision in the product

Local rc.14 integrates the separately proven `files.download?revisionId` snapshot into the actual app and service worker. Free-candidate deployment and actual-account evidence are recorded separately after publication. Production v1.21.0 and automation PAUSED stay unchanged.

The service worker performs two bounded metadata reads around one empty download POST, validates the complete first descriptor and exact Google revision URI, and receives a matching private page acknowledgement before any media byte. An initial completed operation causes no polling; pending operations use the complete opaque name, at most three ten-second polls, a forty-second acquisition deadline and a 32KiB total JSON bound. No per-megabyte metadata polling is added.

The page retains its first immutable pin for the selected-file lifetime. A worker restart, credential renewal or native retry reuses it; latest-version changes cannot replace it. Both Range and full-original recovery use that URI and its size/MIME/resource key. Source denial or missing/unavailable pin terminates with a fixed message and never silently samples latest or enters compatibility. A later Q1 source must match the pinned original descriptor. The public native URL contains only file path, source generation and route marker; revision, checksum, account, credential and provider URI travel through private correlated messages.

Q0 registers its native transport and independent shared acquisition in the existing source/consumer retirement protocol. Cancelling the first native Range detaches that request while the shared acquisition may serve a following Range. Explicit close joins provider JSON reader, pending callbacks, original-byte reader and downstream-consumer cancellation. An unconfirmed barrier stays sticky and blocks a successor. The page drops the selected pin on close/new selection.

Cold first launch waits up to twelve seconds for a controlling worker. Account key/generation, file/session and source generation fence this wait; closing or changing them cannot assign a late native source. The private message receiver is installed before registration readiness.

Independent actual app/SW VM tests cover the first pin, latest A→B drift, worker restart, same-URI401 recovery, malformed private context, operation-name encoding, reader cancellation, uncooperative cleanup, source-pin recovery, retained full-original bytes and cold-controller cases. The discovered account-key wait and stale resource-key/header serialization failures are preserved before their fixes. Final counts and exact producers are owned by `qa/q0-provider-product/native-results-manifest.json` and `full-product-rc14.json`.

Isolated installed Chrome153 decoded a 202253-byte ten-second MP4 through the real app/SW native path, then sought to90% and continued. Actual close reports retirement settled, owner/pin/source absent and sheet hidden. Seven synthetic provider requests: two metadata, one download and four pinned revision ranges. This is native integration proof with a synthetic provider, distinct from the already-recorded real Google disposable A/B proof and forthcoming current candidate playback. Large files, physical Android/iOS, actual hidden return and every original acceptance row retain their own gates.

The source-only materializer now protects public assets and their governing scripts/Worker configuration while unrelated nonpublic preparations can continue. It validates the exact output inventory, reads only fixed-HEAD blobs and rejects publication dirt or output links. This does not export the repository or weaken byte provenance.
