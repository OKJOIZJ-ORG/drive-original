- The first-byte fixture initially had no finite timer. Later reviews exposed three false-confidence gaps—zero-byte chunks, 206 under/overrun, and app retry ownership—and two real races: timeout notification could outlive the stream, and a caller abort with a custom reason could be mislabeled. The final fixtures close each case and keep timeout as the only terminal winner under late competing events.
- The first body-stall tests failed 0/3 because no post-first-byte timer or app diagnostic stage existed. The final matrix also invokes captured cleared callbacks after every competing terminal and delays `clients.get()` to prove the stream cannot outlive its classified error. A transient test-harness hang came from delaying both trace and error lookups with one release handle; removing the trace ID isolated the intended error-lifetime boundary, and the stale process was terminated without touching product services.

One intermediate full audit stopped earlier on the pre-existing reconnect-button visibility assertion; the adjacent complete runs passed and the slow-tail case passed every run that reached it.
- The first frame-watchdog draft treated verified headers as transport start; that would time out before any body byte existed. A dedicated non-diagnostic first-positive-byte worker message now owns that boundary, and exact source generation prevents a late old request from arming a new source.
- Independent review found two real lifecycle gaps: seeking cleared the clock but never re-armed it, and a same-session old frame callback could renew a replacement source. Preserving the transport-start fact across seek and fencing callbacks by source generation closed both.
- A final mixed-version review found that a new app under an old controlling worker could receive no first-byte progress signal. On `controllerchange`, only a current visible pre-byte Range video is reconnected through the new worker with `consumeRetry:false`; started, blob, preview and stale-session sources remain untouched.
- The first seek-clock test correctly failed because no seek owner existed. A related audit fixture also had to acquire a real current player session instead of testing the seekbar in an impossible ownerless state.
- The first tail-index static contract failed because the seed did not exist. Independent review initially flagged the dormant whole-root Pages workflow, but action-time GitHub APIs proved it remains manually disabled and current Pages reads the explicit `gh-pages` tree; the finding was withdrawn after the allowlist build also excluded the QA seed.
- The first large-offset discriminator returned upstream 416 because unsafe request syntax was only parsed after Drive responded. Pre-auth validation closed that defect. Independent review then found two subtler gaps: individually safe endpoints can form an unsafe inclusive span, and an empty present Range header was confused with no Range. Red fixtures reproduced both, zero-length suffixes were also rejected, and a separate omitted-Range GET/HEAD fixture preserved the valid sequential path.
- The first browser large-offset run also returned 416, this time because the old local fixture bound the apparent total to its one physical byte. Separating the safe logical total from the payload made both large offsets traverse the real browser/product-SW boundary; the malformed control stayed pre-upstream, and final disposal proved the QA intercept did not leak into later checks.
- The first faststart attempt used the non-faststart expanded bytes by mistake and correctly timed out. With the pinned faststart seed, holding the initial `bytes=0-` response after either 96 KiB or 160 KiB still left Chrome at `readyState=0`; completing 24 KiB and 64 KiB bounded prefixes while holding a later response also did not expose partial non-fragmented `mdat` bytes to playback. The final browser-compatible discriminator completes the immutable small MP4 seed over two bounded Ranges and holds only its appended top-level `free` tail. Documentation therefore claims whole-file avoidance and two-second progress, not decode from a partial `mdat` or real large-file performance.
- The non-faststart control did not continue sequentially from byte 57,944: Chrome made its own absolute tail request at byte 4,227,072. Withholding only the final byte of that response kept the moved `moov` incomplete and produced the required `readyState=0` negative result; the final assertion follows the observed request rather than hard-coding suffix syntax or an invented sequential range.
- The first `QA-TR-03` browser test proved target frames and stale generation fencing but sampled fixture state only after seeking, so its documentation's cache-before-seek premise was not enforced. Independent review caught the gap; the final test snapshots the fixture before the first seek and requires exact contiguous coverage of the whole 202,253-byte seed plus one and only one held trailing-`free` response.
- Holding the small fixture's trailing `free` response is source cleanup evidence, not seek-specific transport cleanup. The 1/5/9-second targets are already cached, so a larger valid MP4 with distributed samples is required before attributing any pending Range to a superseded seek.
- The first large seek fixture design tagged any request opened during phase A as seek-owned. Removing the real A `currentTime` write still passed because ordinary sequential prefetch acquired that label. The final design first requires a quiet all-terminal baseline and a 500 ms no-seek control, then requires A and B to be non-contiguous requests overlapping their exact uncached GOP windows. Re-running the old counterfactual now fails at that causal boundary.
