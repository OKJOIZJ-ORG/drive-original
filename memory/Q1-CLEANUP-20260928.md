# Q1 rejected-body cleanup termination — 2026-09-28

Observed local rc.9 follow-up to `Q1-AUTH-20260928.md`. Baseline rc.8/`776605b`
reproduces two defects: rejected SW401 cancellation returns generic502 without
aborting the upstream and lets source retirement report success; nonsettling
cancellation leaves the SW promise pending even after caller abort. Earlier auth
lease checks stop replay but do not prove this cleanup.

The SW now gives Q1 rejected-body cancellation a separate two-second wall. Failure
or abort requests upstream termination and releases its signal listener, without
claiming the body actually settled. It returns a fixed `unconfirmed` marker. The
Q1 source marks cleanup failed and reuses its existing false retirement contract.

A small client-scoped Q1 completion fence also covers a discarded old response:
later Q1 reads await all registered cleanup and reject if any is uncertain.
Concurrent success cannot erase another pending/failed cleanup, and new access
credentials/account revisions cannot clear failure. Only confirmed-gone clients
are pruned; the worker lifetime remains the boundary. No reset or credential
purge API was introduced. Generic media and other clients keep existing behavior.
