# Local TS same-player raw head/tail retention

Implemented in `media/drive-source.mjs` and `media/ts-player.mjs`; focused regression tests are `tests/q1-probe-retention.test.mjs`. This is undelivered local work on top of HEAD `ae21f8ac6b34497b3690aef9bc67ecee86a7e927`. Public source31 remains separate. No app/style/index/version/SW/core/probe primitive, frozen31 QA, private input, original media, browser/device or deployment was changed by this unit. Parent owns review/integration/commit/full checks and subsequent native validation.

Observed rc31 Android v2 repeated the same head/tail intervals across the same player's three seek generations. This change addresses those exact repeated probe bodies only. It does not add chosen-window suffix reuse, range coalescing, prefetch or a persisted cache.

Each TS player owns an opaque two-slot source-module retention handle. Only probe callers pass it. The source admits exact head/tail intervals whose starts/lengths are188 aligned and whose length is≤1MiB. Each slot contains an owned raw byte copy plus private account/content/version/knownSHA256 metadata; no parser plan, worker/MSE output, callback, promise, credential or URL is shared. Widest slots remain bounded by2MiB total and are not displaced by smaller fresh subranges. Lookup is exact-interval only; a partial/subrange or no-handle continuous loop performs the normal original Range read.

A new reader still opens with fresh metadata. Every cached logical read still uses the original source owner, account/controller/current/signal/concurrency/deadline checks and fresh preflight and postflight metadata. Only a fully matching knownSHA256 tuple can hit. A missing→known checksum or account/version mismatch invalidates eligibility before a fresh body; old nullable-checksum bytes are never relabeled. A version change during cached postflight is a miss and triggers another fresh preflight/body/postflight sequence. Content/permission/checksum/current-owner denials keep their existing terminal behavior. Metadata checksums remain optimistic identity evidence, not a hash of each raw Range.

Only complete original bodies admitted by unchanged pre/post metadata populate slots. A cache-clear epoch captured before preflight prevents in-flight cached/fresh reads from repopulating a cleared handle. `clear()` invalidates existing slots and outstanding retention; it is not a permanent closure, so a later separately admitted read may populate new slots.

Normal same-player seeks wait for prior source/worker/MSE cleanup before their fresh reader starts. They preserve only raw slots; generation-tagged probes/bootstrap/worker/MSE state is rebuilt. Failure/content/account drift, source503 replacement and final player disposal clear them. The one503 retry budget still belongs to the whole player lifetime. Source retention is cleared on later fresh read failures even if that read has no cache handle. The unchanged continuous loop retains262,144B logical reads,65,536B bootstrap pushes/worker inputs, credit/ACK sequencing, original audio/video packets and GOP preroll.

Source `readsStarted/readsCompleted` count admitted logical reads. `rangeRequests`, `receivedBytes` and `releasedBytes` remain actual original-body transport counters; cached reads add none to those fields. `cacheHits/cacheBytes` separately count cached logical bytes returned after every owner check; `logicalReturnedBytes` includes both paths. Retained slot stats expose only byte/slot counts and≤2MiB ownership, not identity/bytes or JS-heap guarantees.

`verify-local.cjs` performs only local syntax and the focused source/rc19/new-retention tests, then records safe counts/source hashes. Tests distinguish fresh pre/post barriers, exact copied bytes, subrange/size fallback, strong-checksum/version/account mismatch, permission/current-owner rejection, late checksum upgrade,503 invalidation, canceled/delayed/timeout/concurrent reads, clear-during-postflight and rapid-seek/final-disposal lifecycle. Canonical plans/bootstrap bytes and actual synchronous mux output match fresh controls at0/5/11.95s. The TS-player lifecycle test uses a Node MSE-boundary substitute; it does not decode or claim actual native playback. Existing actual31 results and15s failures remain frozen. Native packet/frame/audio/EOF equivalence and real latency improvement require the parent's later candidate validation. No measured speedup is claimed by local request-count reduction.

The independent review identified a fresh-body store invalidation race. `regression-before-after.mjs` omits only that epoch-store guard in an in-memory local counterfactual, leaving product files untouched. Its preflight/body/postflight clear cases retain188B with the omitted guard and0B with the current guard; admitted returned bytes remain identical. `epoch-clear-regression.json` records this controlled before/after mechanism, not a historical deployed failure. Independent review also exercises a separate preflight-clear phase and additional cancellation/account/permission/disposal counterexamples without duplicating the passing focused suite.
