# Q0 optimistic original-byte streaming prototype

QA only. Product baseline 570f9c38506d1e426c33cf65b73836d32bf872c0. No app/SW/media/public changes, browser execution, original mutation, retention change, commit or deployment. Actual rc13 conditional evidence in `../q0-conditional-v2-rc13/live-results.json` reports matching and deliberately nonmatching If-Match both206; JSON ETag cannot be used as an enforced media validator on that observed path.

`openNativeFence(options)` reuses the exact `media/drive-source.mjs` owner. Callbacks supply bounded metadata and original Range responses with existing exact Content-Range/Length checking. The shared source pins headRevision/size/MIME/modifiedTime and an available SHA-256 metadata value; its `version` is informational, deliberately not treated as content-only identity. It is an optimistic observed pre/post fence, not an immutable snapshot or hashing of the fetched range. Concurrent mutation plus stale metadata/ABA is not cryptographically excluded.

`response({range,method,signal})` maps native single finite/open/suffix/no-Range requests to serial chunks at most1MiB. Native Node Response/ReadableStream are used; highWaterMark0 avoids speculative next-chunk pulls. Bodies remain inside Source until postflight passes. HEAD has no body; invalid/multiple/unsatisfiable ranges throw for an adapter to map to416. Responses have exact lengths, Content-Range for206, no-store, and original MIME. At most2 active responses and2 queued/active read operations by default, configurable1–4; overload rejects the individual new request, without unbounded queue growth. Content/owner/cleanup failure retires the lease and errors siblings. `close()` returns the shared sticky cleanup outcome: unsettled cleanup forbids further requests. Callback and browser/native-consumer buffers are outside the one held source chunk measurement. No Blob, complete-file staging or transcoding.

## Integration choice and required remaining work

Prefer deterministic classic-SW materialization of the existing Source plus this small stream owner, retaining the current classic service worker registration. `build.cjs` now produces `classic.expression.js` from the canonical Source plus `owner.mjs`, strips only exact unique module declarations, pins Source SHA, and records producer/inputs/output hashes in `provenance.json`. It evaluates to `{openNativeFence,resolveRange}` and makes no global assignment. The same11 tests pass against the canonical module and the generated classic expression in a separate Node VM realm. Switching to module SW is a broader install/update/cache compatibility change with no benefit to this fix. Do not maintain a handwritten second Source implementation.

One private SW lease per `(clientId, accountGeneration, mediaSession, sourceGeneration, fileId)` must span every native range of that playback. Neither every HTTP response nor SW restart may silently establish a new baseline. Bind the initial content descriptor through a page-owned ephemeral lease handshake; after SW restart require an exact descriptor rebind or fail closed and clear old native buffers. Never put checksum/revision/token in public media URL/cache. Normal credential renewal can change token revision while retaining account and content lease. Any metadata permission/identity loss is terminal; no fallback to unchecked Q0.

Current source pointers: `app.js:startOriginalRangePlayback/buildMediaUrl` increments sourceGeneration and assigns native src; existing TOKEN_REQUEST `mediaMatches()` recognizes only Q1; `sw.js:proxyDriveMedia` registers/retire-fences only `mediaOwner=q1`; `getUsableCredential` requires Q1 retirement protocol only for that branch. Extend these responsibilities explicitly to a separately versioned Q0 lease, rather than pretending native Q0 is Q1. Route Source callbacks directly to existing strict upstream fetch helpers inside SW, not recursively through its media URL. Generalize the retirement barrier so page close/navigation/account change retires all owned Q0 callbacks and waits before transport replacement. Preserve Q1 protocol/retry behavior unchanged.

**Native request cancellation is now implemented:** an idle/queued consumer detaches without disturbing siblings. Cancelling an active consumer aborts that Source and awaits its actual callback/body cleanup, including body.cancel settlement; queued siblings remain blocked. On settled cleanup, the next queued read opens a new Source and compares accountKey/accountGeneration/fileId/headRevision/size/MIME/modifiedTime/permission/trashed and any learned checksum against the same private initial descriptor before requesting media bytes. Missing/changed learned checksum is drift. Version alone is informational, matching the canonical Source contract. No bytes are enqueued after consumer cancellation; EOF detaches its signal and later seeks reuse the still-open Source. Content/owner drift, lease close, uncertain cleanup, or failed reopening terminates every sibling and permanently blocks reopening. Closing during an in-progress reopen waits for that opening Source's cleanup result too. Native browser seek/cancel/SW-restart interleavings remain an integration acceptance requirement; these tests are Node fixtures.

**Verified existing owner contracts:** `app.js` currently has no function named `getCurrentMediaCredential`; the TOKEN_REQUEST responder's local `mediaMatches` explicitly requires non-aborted `q1Playback` and `mediaAttempt.startsWith('q1')` when requireCurrentMedia is true. Therefore current page authorization cannot simply be reused unchanged for native Q0. In contrast, SW `registerQ1TransportOwner`, `Q1_RETIRE_REQUEST`, the generation watermark and cleanup fence operate on generic client/source-generation ownership, not encoded media format; their Q1 names are not evidence that the mechanism intrinsically requires a Q1 decoder. Safest integration is to generalize that shared transport lifecycle with explicit Q0 owner admission and a versioned protocol, keep existing Q1 clients behavior-compatible, and have the page affirm exactly the selected native range lease. The response must prove current account/session/source after any asynchronous credential refresh, as the existing responder already does for Q1. Do not expand permission merely by changing the mediaOwner query parameter.

Keep responses bounded without rejecting ordinary browser request churn: the prototype's active-response cap2 is a QA resource bound, not yet an empirically validated native concurrency policy. Production should queue pending requests with a small bounded admission policy, prioritizing the current seek, and fail closed only on explicit overload. Metadata fetch callbacks must fully consume/cancel within deadlines and expose cleanup uncertainty, as Source cannot observe detached operations hidden inside a callback.

## Verification and cost

`node --test qa/q0-version-fence-stream/owner.test.mjs`:11 tests passed. The same11 passed with `Q0_CLASSIC_TEST=1` against the generated expression. Covers exact finite/open/suffix/noRange bytes and invalid ranges;4.607GB virtual source first bounded read/backpressure; same-size revision drift before/during chunks; sibling failure; idle cancellation; active cancellation with asynchronously draining body before sibling resume; EOF then later seek; changed re-open descriptor; learned checksum disappearance; callbacks refusing to settle; close during re-open; account/session owner loss. No changed chunk is delivered. All ordinary cases have settled cleanup; deliberately held callbacks remain sticky unsettled even when they later return.

`node qa/q0-version-fence-stream/benchmark.mjs` records actual Node native-stream timings and hashes in `benchmark-results.json`. Four1MiB chunks require **9 metadata +4 media GETs** (one opening +two metadata per chunk). Startup includes opening metadata +preflight metadata +chunk transfer +postflight metadata. Steady throughput adds two serial metadata round trips perMiB; at25ms metadata and10ms media synthetic delay, the lower-bound transfer stage is60ms/MiB before scheduling/processing. Smaller chunks reduce first-presentation bytes but multiply metadata cost. These are controlled synthetic measurements, not network/device performance. Physical native playback, actual Google latency, seek cancellation and audio/video first-frame timing remain unverified.
