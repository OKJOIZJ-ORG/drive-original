# Corresponding-source publication preparation

This unit prepares the exact source-built AC3/EAC3 codec's local source/relink publication files. Product logic, Git, public allowlist, service worker, deployment and `distributionReady` are untouched. Public endpoint availability remains the integrating owner's gate.

The maintained package producer is `scripts/package-audio-source.cjs`. It reads an explicit curated list, verifies every previously pinned input hash, retains complete official source archives and emits a fixed-metadata deterministic source tar.gz split into seven assets at most 8MiB each. `licenses/audio-source-manifest.json` binds every part and 43 individual materials. Run `node licenses/audio-source-reconstruct.cjs`, then extract the reconstructed archive. Full reconstruction instructions and license/modification/relink rights are in `licenses/audio-source-NOTICE.md` and the extracted package README. The source archive is not a runtime asset and must not be precached.

Observed verification:

- `node publication-audit.cjs`: exact deterministic regeneration, every public asset at most 8MiB, source/reconstruction/inventory hashes, explicit scope/private-pattern audit, exact target WASM and retained historical manifest hashes. Upstream emsdk release manifests were also compared byte-for-byte against their full pinned source archive.
- `node relink-audit.cjs`: extracted supplied bridge object and static libraries relink to the exact 502,740-byte WASM SHA-256 `48f85a683a94f6b35a21ce33c12a99312ac64e450eca4a9fffba36b5067e83bf`. Generated glue exactly matches the original; changing only two local filename references produces the current product glue.
- `node relink-audit.cjs --compile-bridge`: extracted preferred bridge source recompiles using the extracted full FFmpeg source and supplied generated public header, then relinks supplied static libraries to that same exact WASM/glue. The rebuilt LTO object differs in size/hash due its relocated input path; the final linked outputs match.
- Both relink modes use the hash-verified existing Emscripten4.0.15 compiler with `EM_FROZEN_CACHE=1`. The 1,563-file existing cache stays byte-identical. No compiler install, SDK activation/config rewrite, FFmpeg library recompile, account access or output/volume change was performed.

Complete archive inputs: FFmpeg n8.0 commit `140fd653aed8cad774f991ba083e2d01e86420c7`, Emscripten commit `09f52557f0d48b65b8c724853ed8f4e8bf80e669`, emsdk commit `389a68bc35dcff7ebae4614e1615099dafda00d1`, and original @mediabunny/ac3 1.60.0 preferred source. Original generated FFmpeg `ffversion.h` reports the enclosing app Git description `v1.20.0-130-g7f3ef0f`; that is preserved exact build metadata, not the independently pinned FFmpeg source identity. Newly rebuilding all libraries may change this field. This unit proves same-toolchain relink/bridge reproduction, not a new cross-host full-build result, broad patent clearance or device proof.

`curated-inputs.json` owns the source selection. `curated-commit-manifest.json` lists only maintained publication files and small QA evidence. Do not stage generated `audio-source/`, `tmp/`, `run-relink.local.sh`, or `reconstructed-audio-source-v1.tar.gz`; these local reproduction products duplicate the curated source package. The exact public file list is in `publication-results.json`. No multi-gigabyte SDK, Make binary, raw PATH investigation log, private/browser/account record, media fixture or unfinished application pipeline is included.
