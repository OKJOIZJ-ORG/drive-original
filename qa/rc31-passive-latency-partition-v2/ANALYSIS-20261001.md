## Grounded candidate and checks, not implementation

Use one source-owned admitted-byte read contract rather than duplicate identity logic in the probe/player. A logical cache hit must still run fresh preflight and postflight metadata, current account/source/controller/generation and checksum checks before returning bytes; only a wholly covered original body GET may be omitted. The existing reader's Range limits, shared revalidation, cancellation/deadline/concurrency and optimistic content-admission semantics remain binding (`drive-source.mjs:182–224`). No immutable-revision or per-range-hash guarantee is added by this design.

The smallest within-generation variant is a single-use copied selected suffix, bounded≤1MiB, same reader/generation only. Full coverage can avoid one duplicate body read; partial coverage initially falls back to the current fresh read. The actual startup/seek50 intervals support investigating this variant, but the failed15s seek90 is a counterexample to assuming a whole request saving at every target.

For the slow seek90, the directly supported broader opportunity is bounded same-player raw head/tail retention. A new generation first awaits prior source/worker/MSE retirement, opens its fresh reader, then admits copies only if the full prior account/file/content/version/checksum tuple still matches fresh pre/post observations. Plans, promises, callbacks, worker/MSE state and parsed output are recreated with the new generation. Identity mismatch or null→known checksum changes invalidate cache eligibility and fall back to fresh bodies; they cannot silently retag old bytes. Final widest head/tail copies need≤2MiB of additional player-lifetime ownership, cleared at disposal/content/account change. This costs more lifecycle/metric complexity than a local suffix, but it covers the two actually repeated full intervals on the slow seek. Actual time/request savings remain unmeasured; metadata waits remain.

Required checks before adoption are byte-equal original inputs/bootstrap/worker outputs with188-byte sample alignment, original audio/video/GOP preroll and unchanged262,144B read/65,536B push/credit/ACK sequence; fresh pre/post content/version/checksum-upgrade/permission/account/current-controller drift rejection; settled cancellation/double-seek/stale-output cleanup and memory caps;503 reader replacement with the existing one-lifetime retry budget; partial-overlap fresh fallback and honest cache-versus-transport metrics. Then use a bounded paired cold/warm native replay for target frames, near-EOF/EOF/reopen and audio-preroll equivalence. No performance gain or product implementation is claimed here.
