# Bounded v2 JSON ETag discriminator (rc13)

QA only, fixed product commit `570f9c38506d1e426c33cf65b73836d32bf872c0`. No product change, browser execution, source mutation, consent, or retention change is performed by this leaf. The earlier `q0-conditional-read-rc13` live record remains untouched.

Google's [v2 Files resource](https://developers.google.com/workspace/drive/api/reference/rest/v2/files) exposes JSON `etag` as the file ETag. This does **not** establish that the value is accepted as a v3 media content validator. This probe tests that exact distinction. Metadata ETag changes may also track non-content metadata; even a positive observed result is one bounded provider observation, not universal or immutable-revision proof.

Run producer `node qa/q0-conditional-v2-rc13/build.cjs`; its pinned baseline SHA and unique replacements fail closed on source drift. Evaluate `facade.expression.js` only in the rc13 candidate app lexical realm, then call `(exactCurrentStateFilesObject, freshSwProofHandle)`. Keep both inputs as remote handles. The existing runtime cache-write SW proof's `get()` must provide the actual current controller and `1.22.0-rc.13`; there is no invented get-version message. The result immediately exposes `poll()` and `cancel()`; export only `poll().summary` when done. Release remote handles after completion.

Sequence: fresh v3 identity → one v2 `fields=id,etag` → baseline 2 bytes → v3 identity; then, only for a nonempty strong-shaped v2 ETag, fresh v3 identity → matching 2-byte If-Match → v3 identity, followed by fresh v3 identity → deliberately nonmatching 2-byte If-Match → v3 identity. Same exact account, token/revision/expiry, controller, media/source generations, selected list object, state writer/projection, capabilities, idle and no-write fences as the pinned baseline. Each postflight matches pinned version/headRevision/checksum and current list identity.

Bounds: at most six v3 metadata GETs / 32KiB, one v2 GET / 2KiB, and three media GETs / 6 accepted bytes. Metadata deadlines 10s, media 15s, overall run 60s; cancellation settlement adds bounded cleanup time. A server violating the body cap can deliver an oversized first stream chunk before cancellation; no further bytes are requested or accepted. All URLs, IDs, ETags, tokens, bodies, and filenames remain private. No retries or header bypass.

`conditionalSupported=true` requires matching 206 exact 2 bytes plus nonmatching 412. Ignored nonmatching If-Match gives false. Missing/weak/invalid JSON candidate remains null after baseline. Matching 412, CORS/network failure, owner drift, identity drift, or cleanup uncertainty stops the job incomplete. Fetch TypeError is labeled CORS-or-network, not asserted to be CORS. Nonmatching 412 body is cancelled; completed successful bodies reach EOF. `sourceCleanup.settled` describes local fetch/body callbacks only; generic upstream cleanup remains unknown. Any observed cancellation/release rejection is terminal. No Source owner is opened and no app global is changed.
